# ADR-002 — Instalación Independiente por Cliente

| Campo | Valor |
|---|---|
| Estado | PROPUESTO |
| Fecha | 2026-08-03 |
| Decisión | Cada cliente recibe una instalación Docker Compose independiente y aislada en su propio servidor |
| Fuente | DOC-07, DOC-08 (§19), Constitución P9 |
| Ruta | `specs/001-fundacion/adr/ADR-002.md` |

## Contexto
KONTROL se despliega por cliente. No se comparten base de datos, volúmenes, secretos, procesos, archivos, configuración, identidad de instalación, licencia ni logs entre clientes.

## Opciones
1. SaaS multi-tenant centralizado (descartado por decisión de producto).
2. Instalación independiente por cliente (decisión).

## Ventajas
- Aislamiento total de datos y licenciamiento.
- Control del propietario sobre activación/renovación/revocación.
- Sin acceso automático del propietario a datos comerciales del cliente.

## Desventajas / riesgos
- Costo de operación por instalación → mitigado con scripts de instalación/backup/restore/update y CLI `kontrol`.
- Riegos de clonación → mitigados con identidad persistente y detección de heartbeats.

## Consecuencias
- `compose.yaml` nominal con volúmenes `kontrol-db-data`, `kontrol-storage`, `kontrol-license-state`, `kontrol-backups`.
- Identidad de instalación persistente ante recreación de contenedores.
