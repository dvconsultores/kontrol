## Contexto
Se requiere fuente única, constraints, locks, transacciones, auditoría y reconstrucción de saldos/libros desde eventos.

## Opciones
1. PostgreSQL (decisión).
2. Otra base relacional.
3. NoSQL como fuente primaria (descartado: integridad fiscal requiere transacciones y constraints).

## Ventajas
- Constraints e índices implementan reglas críticas.
- Transacciones atómicas y locks para numeración/control/stock.
- Reconstrucción de libros/saldos desde eventos.

## Consecuencias
- Versión **fijada: PostgreSQL 18.x** (la validación pendiente CL-11/CON-01 queda cerrada por `ADR-D0-001`).
- Migraciones Alembic revisadas; auditoría particionada.

## Actualización en Gate G0 (2026-08-29)

Este ADR decidía que PostgreSQL es la fuente de verdad **en producción**, pero no fijaba el motor
usado para desarrollar y probar. Esa omisión permitió que toda la evidencia automática se generara
sobre SQLite y ocultó un CRITICAL (`KQA-100`, mezcla `Decimal`+`float`).

**`ADR-D0-001` extiende este ADR** con la regla de paridad de producción: PostgreSQL es obligatorio
en desarrollo integrado, integración, contrato, E2E, QA, staging y producción; SQLite solo con
excepción declarada; ninguna Spec alcanza `COMPLETE_100` sin evidencia sobre PostgreSQL.

Ambos ADR son compatibles y complementarios. Este no queda superseded: queda **completado**.
