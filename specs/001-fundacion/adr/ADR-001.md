# ADR-001 — Monolito Modular

| Campo | Valor |
|---|---|
| Estado | PROPUESTO |
| Fecha | 2026-08-03 |
| Decisión | Adoptar un monolito modular en lugar de microservicios para KONTROL |
| Fuente | DOC-05 (§1), DOC-08 (§3) |
| Ruta | `specs/001-fundacion/adr/ADR-001.md` |

## Contexto
KONTROL inicia desde cero. Los documentos maestros recomiendan monolito modular desplegable por contenedores; los microservicios se consideran complejidad prematura.

## Opciones
1. Microservicios desde el inicio.
2. Monolito modular (decisión).

## Ventajas de la opción elegida
- Menor complejidad operativa inicial.
- Transacciones atómicas simples (una base de datos).
- Límites modulares claros en código, datos, permisos, eventos, pruebas y documentación.
- Extracción posterior a servicio solo cuando exista necesidad demostrada de escala/aislamiento/integración.

## Desventajas / riesgos
- Riesgo de acoplamiento si los límites no se respetan → mitigación: contratos internos y ownership de datos por módulo.

## Consecuencias
- Estructura `backend/app/modules/<dominio>` y `frontend/src/modules/<dominio>`.
- Un solo proceso API en 001 (worker diferido).
