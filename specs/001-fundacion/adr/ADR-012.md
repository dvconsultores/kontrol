# ADR-012 — Auditoría

| Campo | Valor |
|---|---|
| Estado | **APPROVED** |
| Fecha | 2026-08-03 |
| Decisión | Auditoría append-only con `AuditEvent` (tenant, company, user, action, entity, before/after, request_id, session, source, reason, evidence, timestamp del servidor), particionada por fecha/tenant; considerar pgaudit para eventos de BD |
| Fuente | DOC-03 (§11, §15), DOC-09 (SNAT/2024/000121), DOC-05 (§4) |
| Ruta | `specs/001-fundacion/adr/ADR-012.md` |

## Contexto
La normativa exige registro automático, inalterable, con trazabilidad e inviolabilidad de eventos. KONTROL exige auditoría integral (UI, API y BD).

## Opciones
1. Tabla `AuditEvent` append-only (decisión).
2. Solo logs (insuficiente: no estructurado por entidad).
3. pgaudit (complemento para eventos de BD).

## Ventajas
- Búsqueda indexada y consulta por entidad.
- Inmutabilidad (sin UPDATE/DELETE físico).

## Consecuencias
- Endpoint de timeline con permisos.
- No eliminar eventos de auditoría (Constitución P5).
