# ADR-004 — Autenticación y Almacenamiento de Sesión

| Campo | Valor |
|---|---|
| Estado | PROPUESTO |
| Fecha | 2026-08-03 |
| Decisión | Cookies HttpOnly/Secure/SameSite para refresh token + access token de corta duración en memoria + CSRF + Argon2id; sin tokens de larga duración en localStorage |
| Fuente | DOC-08 (§15.1), DOC-05, OWASP |
| Ruta | `specs/001-fundacion/adr/ADR-004.md` |

## Contexto
El Estándar de Frontend prohíbe almacenar tokens de larga duración en localStorage (FR-036). Se requiere rotación de refresh, revocación de sesiones, cierre en todas las pestañas y MFA preparado.

## Opciones
1. Access + refresh en localStorage (descartado por XSS).
2. Access token en memoria + refresh en cookie HttpOnly (decisión).
3. Sesiones server-side puras (evaluado; se mantiene tabla `Session` para revocación).

## Ventajas
- Mitiga exfiltración por XSS.
- Permite revocación y cierre en todas las pestañas.

## Desventajas / riesgos
- CSRF → mitigado con doble cookie/CSRF token y SameSite.
- Complejidad multi-dominio → documentada en despliegue.

## Consecuencias
- Contraseñas con Argon2id.
- Tabla `Session` con hash de refresh token, rotación y revocación.
- Contrato en `contracts/api-contracts.md`.
